## 实际业务覆盖

正常导航从实际首页进入工单列表，搜索并点击工单，点击客户资料、查看全部跟进。详情中的客户、正式订单、合同、质保分卡保留当前产品语义；跟进摘要最多最近两条，完整时间轴显示全部 3 条。

零、一、多及故障状态通过既有、同一角色工单作用域的 R1 形状只读夹具提供；没有执行接单、订单写入、签署或生产请求。客户空态是成功读取后可见字段配置为空，不把读取失败或未知伪装成空数据。新测试同时验证读取失败文案与空记录文案不同。

登录页面走真实退出/入口/选择/输入校验路径。旧测试固定要求“协议未配置”，在本机已有公共协议 URL 时会误失败；现验证配置和未配置两种 UI 状态，保留主动同意协议和受限快捷登录。未发送短信、提交协议或执行真实认证。

## 复审追加：仅明确读取失败使用错误语义

复审发现订单与跟进的明确读取失败仍使用中性灰。本次最小修正共享档案卡的语义 class，颜色只由雨虹 `detail-archives.scss` 的 `--yh-color-status-error-fg`（#B42318）提供；修链样式未修改。

- 跟进只在 `activityReadState === 'failed'` 时使用错误色，读取未知、不可读取、无权限及成功空态保持中性。
- 订单 browse 的终止状态同时包含无权限、未知等情况，当前只公开统一错误文案而未公开分类。为避免把整个终止状态染红，仅对“暂时无法读取正式订单，请稍后重试。”这一明确读取失败文案、且处于失败状态时添加错误 class；权限、会话失效、身份/数量异常及其他未知情况不因此染红。没有修改报价 browse store 或扩大协议。
