## Narrow implementation

- H5 text delivery gains an optional post-native-commit observation and an IME-aware reconciliation entry. `AppInput`/`AppTextarea` expose opt-in `reconcileOnCommit`, default false. The existing generic R1 field control opts in because its host can atomically reject a draft. After Vue updates, the binding copies the accepted prop value into its native/Uni state without emitting a synthetic input or changing parent draft state. Uncontrolled/opt-out consumers retain prior behavior; MP/App retain ordinary string delivery. Preedit is not overwritten by this reconciliation, and an identical final IME commit can still reconcile a rejected value.
- A build-time H5-only compatibility plugin transforms only the exact pinned Uni picker module in memory. It owns that instance's open/close timers and epoch, cancels them on unmount or superseding activity, and verifies captured root/picker identity before cleanup. Existing SDK delays, controls, values, animation and DOM placement remain. No global runtime timer patch or dependency-file edit is made. Unknown SDK bytes or an H5 release bundle that did not apply the compatibility transform fail explicitly. The normal app configuration installs the plugin before Uni; other platform configurations do not apply it.

There is no whole-form/field remount rollback. The normal H5 tests verify original input/date DOM handles remain connected, parent props remain authoritative, and valid date state survives a rejected text update and continued visible interaction. The pure helper still rejects trim/omission instability; no catch/fallback or permission relaxation was introduced.
