# Ordinary first-create field plan

The normal forms version1 first-create entry now builds one plan entry for each configured field. A field chooses its value adapter; the presence of another supported field kind does not select a different form writer. File fields additionally require the existing owned picker/queue/receipt session. The older choice, Switch/Rate, Cascade and transitional mixed reports describe earlier bounded slices, not the current ordinary routing architecture.

The target is a positively verified ordinary non-special collection with exact string Ext.type `0`, zero records, complete 1–50 metadata rows and the current version1 create-only grant covering every field ID. Actor, tenant, role, listed work order, workflow/run/node/definition, raw source identity and private reader lease remain mandatory. Read capability, mapped purpose, a supplied plan or uploaded URL is not write authority. Unknown rows are neither filtered nor relabeled readonly. Version 2 grants do not select these new field capabilities. The already-supported v2 scalar/large-subset and default-image-plus-scalar protocols retain their original bounded adapters and field domains; they are not reinterpreted as grants for the new plan. Repeat/appointment/typed adapters retain their separate contracts. Historical minimal reader adapters without the ordinary source interface retain their old scalar API only; they do not establish the normal App's type0 route.

## Per-field contracts

| Configured field | Ordinary create contract |
| --- | --- |
| Text, textarea, phone, IDNumber, number, digit, date, time, datetime | Existing Runtime codecs and omission; required/visibility and finite values checked. This does not certify every backend format or custom verification protocol. |
| Radio and single Select | Scalar only, verified flat scoped Code provider and exact option IDs. |
| Checkbox and explicit multiple Select | Ordered unique known string IDs, at most 30; no sorting, trimming or guessed labels. Optional absence/empty array omits; required cannot omit. |
| Switch | Exact strings `1`/`0`, with no automatic false/default. Global Runtime Boolean compatibility remains unchanged for other consumers. |
| Rate | Numeric safe integer 1–5, no fractions, numeric strings or invented initial score. Optional empty/absence omits; selected0 is invalid. |
| Single Cascade | Existing verified scoped tree, complete ordered root-to-leaf string path, root leaf accepted. Repeated values under distinct ancestors remain valid. Depth 20/node 5000/value 256 are parser safety bounds, not backend business maxima. Multiple/prefix/custom selection protocols stay unsupported. |
| File | Existing default-image adapter, PNG/JPEG/WebP MIME/extension/HTTPS checks, exact R1 object arrays and field/session/epoch-owned receipts. Known max 0–10 is enforced; max 0 allows only omission. Unknown tool/fileType/provider protocols stay unsupported. |

Strict own undefined/null, malformed objects/arrays, unknown IDs, identity collisions and reserved storage keys remain distinct from valid absence. One unsupported writable field prevents creating a smaller synthetic authorized schema. Readonly rows or mismatched fillable IDs cannot be bypassed by omission. Metadata ordering/renaming does not choose a route.

Known top-level Runtime conditions use the same field plan. Draft updates compare raw, controller-wire and stable-wire visibility/required/capability states before committing local changes. Hidden new values may be cleared only atomically; trim/omission that changes those semantics is refused with the original draft retained. Cycles, undeclared/nested controllers, unknown condition protocols and file-as-condition-controller remain unsupported. Hiding an owned/pending attachment is not cancellation: the provider preserves the whole draft unless the independent queue proves omission safe. Existing records are never cleaned by this create transition.

## Source, media and transaction boundaries

The source reader retains per-field raw metadata checks. Only an existing default-image row may use its previously accepted absent multiple/operationType defaults and numeric required form. A neighboring scalar, choice or Cascade row still needs its own exact raw authority metadata; file defaults do not repair it. Optional file max config accepts only the established numeric bound; custom controls/tools remain closed. The reader issues the same sealed ordinary route with no new HTTP request or fabricated source identity.

The media engine now accepts a trusted plan validator for non-file values. It still checks every owned task, including pending/failed/ambiguous tasks whose optional field was omitted; it does not import foreign tasks or promote URL-shaped values to receipts. Cross-field and cancelled-epoch copies cannot authorize another value. Picker cancellation, stale callbacks, MIME/URL checks and local cleanup remain the existing queue lifecycle.

All kinds use the existing normal forms storage/action adapter: preset 1 root only and preset 0 root plus EXTS mirror. No global storage rule is inferred from field type or another legacy submit entry. Raw ACK and private original readback check exact declared root/EXTS slots, scalar types, ordered arrays, file objects and optional omission. Within the unified version1 path, a bare ID ACK cannot replace those checks; the separately retained historical v2 image adapter keeps its prior receipt contract. Two existing synthetic image fixtures now return the full synthetic raw ACK; their legacy-compatible raw field metadata is unchanged. Intermediate comparison selects the per-field file/string-array comparator rather than treating every array as a file array.

One upsert plus one complete updateExts remains the successful save-only protocol. Full unrelated node EXTS is preserved. Duplicate clicks, stale/observed-revoked authority, fresh metadata/provider changes and uncertain responses cannot automatically replay; an observed v1→v2 grant withdrawal stays revoked even after restoration. Draft arrays and file descriptors are copied before awaiting reads. Process, append, complete, delete and existing file edits are not granted by the plan. This is not cross-client CAS.
