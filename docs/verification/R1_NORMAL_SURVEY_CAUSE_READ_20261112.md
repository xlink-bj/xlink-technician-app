# Normal Workspace readonly Survey cause experience

This private candidate connects the existing cause experience and authenticated cause provider to the existing normal Workspace controller. Data adaptation and experience selection remain separate. It adds no renderer, schema engine, draft store, backend flag or write protocol.

## Consumed contract

The normal host uses the existing `surveyLeakageCauseExperienceFor` binding: a unique single-select trigger and multiple-data value row, their verified field identities, supported metadata and Survey purpose together. Purpose, forms/repeat, DTO name or an arbitrary field shape alone does not select the experience. The representative synthetic fixture uses four captured metadata rows: part, width, trigger and saved causes.

The first supported dedicated read binding uses the captured preset-1 root contract. Its original current normal snapshot and record must retain private reader identity; raw tenant, record identity and saved identifiers must agree. Noncanonical/conflicting EXTS copies, copied records, unsupported binding or unavailable/hidden projection do not acquire dedicated labels. The original normal reader and generic saved-field display remain responsible for other cases. This is a narrow presentation predicate, not a replacement Survey codec or a new storage policy.

Conditions, applicability, field identity and readonly context reuse existing domain/field projection functions. Saved identifier order is preserved. Labels come from the existing provider; unknown or ambiguous provider IDs remain unresolved. The provider still returns all groups, with current part affecting presentation priority rather than becoming a new server filter.

## Lifetime and authority

Provider results belong to one current snapshot, actor scope, configured tenant, work order, node and view generation. Fresh reads and leaving the view invalidate previous results. Observed identity, source or metadata loss cannot revive the old binding after restoration. The normal Panel retains ownership of every other field, scalar, draft and read lifecycle; the new optional field slot defaults to its original rendering.

The existing cause component receives a readonly view, cannot open its picker, and exposes no normal-host mutation callback. This mode does not instantiate or populate the legacy editable Workspace store and cannot fall back to it when the view disappears. Calling the existing component without the new readonly input preserves its original editing behavior. Grant issuance, normal save/EXTS/ACK, Process, upload receipts, existing editing and uncertain-result handling are unchanged.

## Executable evidence

The initial actual-controller/SFC regression read the saved cause identifiers and numeric zero but showed only unresolved identifiers and made no provider query. The implemented tests use the actual normal reader, provider adapter, ActionContent, Panel and existing cause SFC. Normal App browser cases navigate Login → list → Detail CTA → Workspace and cover readonly labels, Back/reentry, tenant rejection after a valid read, ambiguous labels, metadata replacement, completed late responses and logout/new-role rejection. Module/SFC negatives additionally verify that scalar and cause content both disappear on scope/identity/leave changes.

Reproduce the bounded suites with the repository's installed tools:

```sh
VITE_XLINK_ENVIRONMENT=test pnpm exec vitest run tests/engineering/normal-survey-cause-read.test.ts
XLINK_H5_NORMAL_SURVEY_CAUSE_READ=true pnpm exec playwright test --config config/playwright/normal-survey-cause-read.config.ts
```

The opt-in flag is test discovery only. The browser config uses the existing normal read rollout with writes off and no grant; it uses Chromium by default and independent output/JSON paths. All new readonly ledgers contain zero business commands, uploads, Process, unexpected requests and browser errors. Exact counts, final byte boundaries and retained initial fixture/tool failures are recorded in the private delivery receipt. Earlier public main CI is not evidence for this new candidate.

This proves synthetic normal-App readonly consumption, not real Java/DB, production configuration, native behavior or editable Survey experience. Other preset/storage contracts and other dedicated experiences are not newly established. The three reserved data adapters are unchanged. No complete project, backend DTO repair or additional write capability is claimed.
