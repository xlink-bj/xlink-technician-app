- 共享模板和业务：`src/pages/work-orders/work-orders.vue`、`src/features/work-orders/card.ts`；读取、权限、分页及接单协议保持现有逻辑。
- 构建选择的页面皮肤：两品牌 `src/brands/<brand>/work-order-list.scss`。

- 图标颜色：修链 `_list-tokens.scss` 保留原色值，雨虹 `_semantic-bridge.scss` 绑定自己的反馈色和中性色；`card.ts` 只提供装饰角色名，不决定权限或状态。
- 检查与测试：`check-ui-governance.mjs` 继续检查外置品牌样式；`brand-list.spec.ts` 运行真实 App；读取失败、空、加载和分页由测试目录内的合成 Port 提供，不能执行真实业务命令。

报价局部文件未修改。Production/Beta 写入、上传、签署及触达仍关闭。

## 改动与清理

雨虹使用更正后 3 页 PDF 与 v2 tokens 的 16px 页边距、4/8px 控件/卡片圆角、16/14px 正文/辅助文字、至少44px触区和独立主操作/链接/焦点语义。长称谓和地址允许换行，不以截断隐藏服务信息。

原骨架两层同选择器规则合并为最终生效值；未按重复数量删除其他有效规则。搜索按钮增加 button/aria-disabled 语义，真实 uni-button 禁用背景修复另见 `49ebeef34147b91d5ad9b0ec2b23343d6e760076`。

截图发现列表原有条件链被接单弹窗的独立 `v-if` 打断，使已加载/失败后仍呈现行内加载条。已将弹窗移出读取状态条件链，H5 对所有稳定状态断言无错误加载条。

## 分开交付的原生缺陷与门禁

本轮实际进入预约工作台发现 MP 会丢失从 Vue SFC 导入的命名函数 `useSurveyCompleteConfirmation`，导致 setup 错误。它不由列表皮肤引起；原生修复作为下一独立增量保留、验证和提交，不能把构建成功计作该运行路径通过。

当前工作区修复已使预约真实渲染，输入回填与底栏可见已观察，软件键盘尚未实际展开，键盘遮挡仍未验收。Native Nightly 2.02.2608112 与 automator 0.13 的启动版本字段不兼容；已通过现有授权窗口读取实际基础库3.17.6和设备信息并保存真实截图。未注入虚假的键盘高度或业务成功状态。
