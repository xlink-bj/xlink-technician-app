# Normal forms and Repeat content in Action Workspace

The batch published at `6cc51d0de10314b78106c386443b3d4a63aa2b12` moves the existing normal form reader and controller into the Action Workspace content host. The Detail page offers the real current-task CTA and does not mount a second normal editing panel when the normal reader is enabled. It reuses the existing Shell, normal provider, private source proofs, upload session and ActionDraftRepository; it does not wrap the legacy Overview's synthetic draft store.

Host eligibility is a read-side decision: an active current forms/repeat task with a definition, the existing normal-reader availability and existing non-production gate. There is no additional default-off rollout switch. The existing reader gate remains deliberately narrow: DEV build, dev environment, exact http://127.0.0.1:5189 with same-origin /xlink/wm, normal business mode (Mock and H5 Mock E2E off), no separate auth API, and the original readonly or explicitly scoped write configuration. This does not enable a native or production entry. The Runtime descriptor and general adapter remain disabled for this action. Each write still requires the original normal provider's exact current grant, actor/tenant/session/role, node/run/definition, records and private reader lease. This change adds no field types, grants, command protocols or production capability. Quote edit provenance, receipt locks and browse refresh behavior remain unchanged.

The normal content branch returns before generic dynamic-form reads, draft identity or media recovery. Back awaits the existing normal controller's queued local persistence, reports a failed write and retains the page; it does not treat the generic draft flush as a saved normal draft. Reentry performs a fresh authoritative task read. Explicit local restore remains separate from reading a saved record. A changed event rereads authoritative Detail with a per-refresh ticket and the same identity/current-task/reader-gate selector used at initial load; stale or mismatched responses cannot replace the host. Observed source-node-kind changes remount the owned Panel and invalidate its old reader snapshot; a Repeat ACK does not establish a workflow transition. View ownership prevents an old panel's late unload from clearing the singleton reader already claimed by a newer page.

The preceding hidden-clear regression is retained as a separate repair. The original source codec recognizes its exact legal live clear sentinel; the current normal provider exposes only omitted field IDs to generic local recovery, bound to the exact snapshot and current authorization. Generic recovery checks strict empty-string shape, unique known identity, fill/readonly permissions and stable reprojection before excluding that sentinel from disk. Disk restore rejects hidden own keys. Same-scope live memory retains the legal wire sentinel; it is not interpreted as disk recovery. No arbitrary hidden empty value becomes writable.
