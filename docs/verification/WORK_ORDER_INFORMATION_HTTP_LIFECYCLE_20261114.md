## 缺口与补验

已有资料测试覆盖配置失败、合成 ApiReadTransportError、配置在途撤权及角色 token 失效。本批补的是实际 HTTP 状态映射经过 `UniApiReadTransport → TechnicianApiReadAdapter → WorkOrderDetailStore` 的链路，不重复十项列表/分页权限撤销 H5。

新增 `tests/engineering/work-order-information-http-lifecycle.test.ts`，12 项：

- 配置及字典各自的 HTTP 401/403：刷新前曾成功展示，刷新开始清除旧资料；拒绝结果无 detail/fallback，401 触发会话失效一次，403 不注销会话；拒绝后不继续读 activities（4 项）。
- 配置/字典 HTTP 503：分别保留已许可固定展示或标明选项未核实，不注销会话（2 项）。
- 旧配置/字典迟到 401/403：新会话已完成 B 的列表和详情后释放旧 A 响应，不能清除 B 或注销新会话（4 项）。
- 字典第一页 50 行、共 51 行，第二页等待时切角色或更换租户；即使第二页以 503 失败，也不得发布旧资料或降级回退（2 项）。

HTTP executor 完全注入，未知请求另行收集并在每例结束断言为空，避免被可选读取的失败回退掩盖。没有真实网络、Java、Mongo、生产权限或媒体副作用验证。
