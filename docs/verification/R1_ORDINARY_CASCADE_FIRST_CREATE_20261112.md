# Ordinary single-path Cascade first create

This private candidate is based on `c0b2c041e62e97f57d02c2c6088b1f8bd6c2318d`. It adds a bounded normal forms strategy for arbitrary Cascade field names and existing scalar mixtures. It is not a Survey part profile, a production configuration claim or a universal legacy leaf rule. The original seven-path source slice included no backend, shared Runtime, reader API, panel/control/input, SDK compatibility or CI change. A later separate private workflow step runs its dedicated H5 suite and always archives its independent output.

## Positive source and permission

The normal provider must have its actual current private `currentFormsCreateRoute`, exact string Ext.type `0`, ordinary non-special collection and matching tenant/order/run/node/definition. It preserves the exact version1 create-only grant, complete field IDs, handler/role/listed-ID identity, reader generation and zero-record restriction. The route already checks complete raw metadata, empty/default frontend config and raw boolean multiple. The mapper omits false, so absent mapped multiple means false only under this positive raw provenance; true or missing/nonboolean raw multiple cannot select this strategy. Read capability or a valid-looking tree is not a write grant.

The helper supports 1–50 complete writable mobile fields, at least one Cascade, no conditions/readonly/presentation-only/unknown rows. Other arrays, file, Switch/Rate, typed/special collections, >50 metadata, edit/append/complete and unverified providers remain closed. Scalar Radio/Select need verified scoped flat Code options; other supported scalar types retain their existing Runtime codecs. Nothing filters unknown rows to construct a smaller authorized schema. The provider binds the exact snapshot identity/seal only after private route and grant checks. Copies are unbound; an observed schema/current failure permanently revokes that binding, with provider authority reflecting the revocation. A new legitimate load may bind a new snapshot, never revive the old one.

## Complete ordered path contract

A Cascade value is an ordered array of exact nonempty string IDs traversing one verified root-to-leaf path. Each segment belongs to the current ancestor level and the final node has explicit empty children. Root-level leaves are valid. Repeated values at different ancestors are valid (`same → same → leaf`); no global Set deduplication, sorting or trim is used. Scalar/prefix/cross-branch/reversed/orphan/unknown/blank/control/mixed/object/null/own-undefined inputs are refused. Sibling ambiguity, duplicate raw node IDs, inconsistent parent/provider/tenant and missing leaf children are rejected by the existing scoped reader parser. Current Runtime prefix/scalar compatibility and existing read display are unchanged.

Depth20, total5000 provider nodes and value256 characters are existing client parser safety ceilings, not backend business maxima. The existing wire array ceiling30 is looser than this strategy's path-depth ceiling20; both are preserved. Optional true absence or `[]` is omitted from root/EXTS; required absence/empty is refused, and an entirely empty normalized patch is refused. Own null/undefined is malformed rather than optional absence. Scalar own null/undefined/arrays/objects are also refused in this new strategy. Normalized path arrays and drafts are cloned/frozen; save snapshots caller arrays before awaiting a fresh read.

## Save and readback

The normal existing transaction remains one upsert followed by one full workflowNode/updateExts and authoritative readback. Preset1 stores root only; preset0 uses the existing root+EXTS mirror. Exact ordered path values, optional omission and root/EXTS conflicts are checked against ACK and reader private originals, not just flattened mapped display. Scope/ID/count and unknown existing node EXTS protections remain. No Process/upload/delete operation is opened. Multiple click, observed grant/switch/actor/listed-ID loss, fresh metadata/tree/permission drift and late ACK are rejected. Failure after a dispatched upsert stays uncertain/locked and cannot automatically retry or associate a second write.
