## Model-layer principles

1. **Source objects are not UI objects.** Only the API adapter interprets R1 `nodeDef`, `exts`, `workflowId`, paginated response wrappers and alternate ID aliases. Stores/components depend on `@shared/ports`; no R1 raw entity is installed directly as a UI permission.
2. **One business identity per row.** A non-empty second alias is a corroborating value, not an alternative candidate. The shared `consistentWireIdentity` helper in `src/adapters/common/records.ts` enforces this for model boundaries that were previously inconsistent.
3. **Unknown is not false, nor empty.** Missing node type, missing `exts.formList`, unavailable catalog, unsupported field/control or incomplete page is not a reason to fabricate a default workflow, zero records, source type, SKU, price or completion.
4. **No promotion through fixtures.** Mock fixtures and code-level shape guards do not expand Production read transport allowlists, establish authorized FormData values, or enable business writes; the UI may only expose capabilities whose existing guard accepts the live identity.
5. **Cross-platform invariance.** The projection and pure tests run without WeChat/native APIs, while H5, MP-WEIXIN and App builds remain independent build gates; WeChat simulator click and device UX are distinct acceptance evidence.
