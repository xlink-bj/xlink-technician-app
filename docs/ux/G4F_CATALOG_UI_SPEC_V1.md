## 2. 核心页面状态和导航
- 工单详情 Workflow “报价”Action → 公共 ActionWorkspaceShell → 维修部位路径/描述/工程总量 → **选择产品** → 本第三页目录。
- 商品目录不新增正式订单，也不是订单概览、支付或报价提交页面。进入时保留当前 groupId、已填写的维修部位数据、可回退工作台。
- 默认可见套餐；顶部四分类：套餐、工序、材料、机措。搜索内容/过滤与分类切换保持 R1 既有语义；避免工作台再复制一套品类逻辑。
- 套餐卡 CTA “查看并配置/选规格” → R1 对应的**既有套餐规格、材料层级/SKU、包含的工序/材料/机措、数量和已选状态**业务过程。可使用当前新端已验证的受控配置页；无需每一操作重新创作产品流程。
- 工序、材料、机措在各自类别中遵从 R1 的适用入口和编辑方式；无规格可直接选择/加入、有规格的按 R1 进入规格选择。对已选商品需要呈现数量或已选状态、可修改/撤销、回到原部位；具体命令须通过当前合同验证。
- 分类/搜索/规格/选中数/返回场景需验证：R1 中每个部位的已选状态与搜索等是否按分类、分组隔离；新端不要无意跨部位覆盖或清空草稿。

## 3. 设计到代码的几何与视觉规范 (390×844 CSS px，业务页)
- 页面背景：#FBFDFF → #F0F6FF → #F5F8FD 浅冷白渐变。仅作用到选品 UI，不改变全局 Shell。页面边距15px、垂直自然滚动和安全区保证。
- 目录独立页标题“服务目录”，返回（原维修部位工作台），右侧“选品中”轻蓝标签。导航高度约55px；不得额外复制通用工单摘要或破坏当前 Action Workspace 的 Page Shell。
- 顶部维修部位上下文卡：白色、圆角15px、边框#E8EEF8、阴影 0 5px 18px rgba(21,64,118,.055)，padding11–14px，最小高度约70px；左侧序号31×31px浅蓝，label“添加至当前维修部位”，具体路径显示真实 repairPartPathLabel，右侧已选数由真实当前组数据计算。
- 提示标题“选择服务项目”19px/800，说明11px/regular，右侧“第2步·选品”浅蓝标签11px。仅为视觉导航，不新增业务步骤状态机。
- 主要白卡：1px #EDF1F7，圆角17px，阴影 0 8px 26px rgba(28,68,128,.052)，padding10–12px。四分类导航高48px；未选字14px #8294AC，选中#136CEC/800并有3px蓝色底线。
- 搜索输入：高44px，圆角12px，底色#F7FAFF，边框#E1EAFA，图标与输入占宽；按钮浅蓝#E7F1FF 字色#1B70E8。搜索placeholder按当前分类实际语义变化，不硬编码单一套餐搜索。
