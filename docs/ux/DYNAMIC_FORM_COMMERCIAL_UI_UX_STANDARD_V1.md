# 动态表单商业化 UI/UX 标准 v1 — S01–S05

**产品设计结论：S01 主表单 + S02–S05 局部交互的视觉方案已获用户认可；设计稿不再调整。**  
**实现状态：DESIGN_APPROVED / IMPLEMENTATION_PENDING**，不是 `COMMERCIAL_UI_IMPLEMENTED` 或 `PRODUCTION_API_VERIFIED`。  
2026-10-14，M1 / S2 Commercial UX/UI。

## 0. 设计范围与权威

- **视觉基准：** 用户已认可的 S01 单手机主表单图，以及 S02–S05 四手机局部交互设计图（本项目对话中提供）。后续前端应按其视觉语言落实，不得以另一套样式替换，也不得把现有 IA 改成固定步进向导。
- **信息架构权威：** 新 App 已运行的 `ActionWorkspaceShell → GenericDynamicFormActionContent → AppField/Control + DomainExperienceSlot → ActionBar`；现有勘查的部位、测量、照片、渗漏原因分节保持。UI 设计稿中的演示工单、数值、媒体图片、计数并非生产数据，也不是字段新增授权。
- **字段与操作真值：** 运行时有效 FormDef + 字段级 Field Runtime + 服务端已授权 Capability/Port。R1 的 Vant cell、级联、上传、底部弹层属于成熟交互参考；**不拷贝 R1 混合的 InspectionAppointment 数据模型**。
- **本标准的核心原则：能在主表单内直接操作，就直接操作。弹层不是为了展示设计效果而增加的新步骤。**

## 1. S01–S05 是一套页面 + 局部交互，不是五个页面

| 设计 ID | 形态 | 何时使用 | 必须遵循的行为 |
|---|---|---|---|
| **S01 主表单** | 唯一业务主工作台，**主承载面** | 进入勘查后持续填写 | 保留已确认 IA：工单上下文 / 草稿提示 / 维修部位 / 现场测量 / 现场照片 / 渗漏原因 / 底部操作；可见行、顺序及必填由 Runtime 决定；视觉采用已批准卡片、字段、留白与状态语言 |
| **S02 维修部位选择** | **仅在点击级联字段时**底部选择弹层 | 部位确实需要在层级选项中挑选 | 支持父/子层级、当前路径、已选择态、取消/确定/回填；历史 Survey 的 `part` 为 `cascade` + `multiple:false`，不可照示意稿把它变成多选；后续有效 FormDef 若不同则以它为准 |
| **S03 渗漏原因选择** | 点击渗漏原因后显示局部选择弹层 | 多类别/多选不适合在主表单直接摊开 | R1 风格分类/选项/已选结果/确认，已选值回到 S01；选项提供者来自当前维修部位；失败、缺失选项、只读明确提示，不虚构选项 |
| **S04 媒体预览与管理** | **S01 内联为主，必要时才进入大图预览/管理界面** | 图片已在表单可直接拍照、上传；用户点缩略图时需要看大图或管理 | **默认在 S01 媒体字段直接拍照/选图、显示缩略图、进度、失败/恢复、数量/上限和删除入口；不为拍照/上传再弹一个自建 S04 窗口。** S04 四宫格图仅规范“查看多张、上传/失败状态、放大预览及管理”的局部效果，非必经步骤 |
| **S05 完成勘查确认** | 仅必要时调用的最终确认弹层 | 点击主表单“完成勘查”且 Runtime 满足提交前置条件 | 只用 Runtime 可信的必填结果检查；未满足时停留在 S01 并定位相应字段/提示，不弹出可确认成功的页面；确认成功只在真正工作流响应成功后展示 |

**S02–S05 的弹层外观与控件样式沿用已批准设计，但触发方式由任务实际需要决定。尤其不能把 S04 当作所有拍照/附件字段的额外入口。**

## 2. 通用动态表单字段呈现规范（可横向复用）

### 2.1 内联优先（重点冻结条款）

1. **普通输入 / 现场测量**：文本、数字、面积、长度、备注等在 S01 中**直接输入、修改并即时展示校验**。**不得**为常规测量另建“测量填写弹层”或固定步骤页；字段出现与否、必填及单位以当前 FormDef/Runtime 为准。
2. **图片/文件**：每一条有效的 `image/file` 字段在主表单**直接展示采集入口**（拍照/相册或受支持的文件选择）、缩略图、上限、媒体状态、单项重试/删除，按字段 `fieldId` 分别记录。只有需要大图查看、多张管理或原生相机/相册选择时才使用系统/局部交互，不增加第二套“先打开照片窗口再上传”的人为流程。
3. **短选项**：若少量选项适合直接触达，`radio/checkbox/switch` 可**内联**展示；长列表、多级 `cascade`、复杂多选使用 S02/S03 型聚焦选择器。选择器不是每个字段的强制步骤。
4. **分节**：使用源 FormDef 的 `title/gap/section` 呈现语义分节；Survey 的视觉章节不应被写死成六项固定步骤。动态字段可增减、顺序可变，同一字段家族共享视觉控件，不复制布局和验证逻辑。
5. **条件显示**：先选择维修部位后，测量及相关媒体字段按 Runtime 的 dependency/visibility 变化；不得根据视觉稿新增、删除、合并 `valueKey`。`fieldId` 必须保持行级唯一，同名 `valueKey` 可以重复。
6. **布局与操作**：S01 保留工单上下文、简洁的状态提示、单列有序卡片/字段、固定安全区 ActionBar。底部按钮**保存表单（次要）/完成勘查（主）**与表单可滚动区域职责独立；键盘弹出仍可访问当前输入和相关错误。
7. **状态真实性**：本机草稿自动存储 ≠ 业务保存成功 ≠ 工作流完成；“尚未上传的本地图片”不表示远端已上传。加载、错误、只读、权限阻断和结果不确定必须明确，不能用视觉展示伪成功或盲重试。
8. **动作边界**：S05 只是 UI 确认层，不得绕过现有 Capability、数据有效性与工作流写门禁。尚无授权的 Production 测试、真实保存、上传、完成动作继续保持禁用或清楚标识。
9. **视觉应用**：采用 S01–S05 已批准配色/边角/层级/状态标记，但不得把“设计稿中的示意图、工单号、照片数量、完成数量”硬编码成业务内容；任何测试数据标注保持诚实、次要。
10. **复用门槛**：`AppField/Input/Textarea/Choice/Cascade/Media/ActionBar` 为通用呈现；维修部位依赖、渗漏原因 provider 属于 `DomainExperience`。具备第二个已验证使用者时，才抽出更高一级通用交互组件。

### 2.2 字段与局部交互决策表

| 字段/动作 | S01 直接操作 | 何时使用局部界面 |
|---|---|---|
| 现场测量：面积/长宽/高度等 | **是：普通数值输入，含单位和错误提示** | 默认**不需要**弹层 |
| 现场照片：大面全景/渗漏部位等 | **是：直接拍照/上传、缩略图、状态、重试、删除** | 点击已有图预览大图、多图浏览/管理（S04）；相机/相册使用系统 UI |
| 普通单行/多行文本 | **是** | 通常不需要 |
| 简单单选/开关 | **可以内联**，由选项多少和任务性质决定 | 选项过多或平台控件约束时使用聚焦选择 |
| 维修部位级联 | S01 展示当前选中路径并提供点击修改 | S02 级联选择 |
| 渗漏原因复杂多选 | S01 展示已选摘要/触发入口 | S03 分类多选 |
| 保存表单 | 固定 ActionBar 次按钮 | 不因视觉设计强制另开新页 |
| 完成勘查 | 固定 ActionBar 主按钮，未满足时不可执行 | 仅通过 Runtime 前置检查后，按需要 S05 确认 |

## 3. 实施验收（面向 S2 工程）

- [ ] **IA 不变**：S01 仍是真实主 App 动态表单工作台；没有发明新的步骤/页面，也不改已认可登录、工单、预约。
- [ ] **内联填写可达**：在 375×667、390×844 用同一真实 H5 流程，直接在 S01 输入面积、直接触发媒体选择并查看状态，不必经过 S04 的自建弹层。
- [ ] **级联/原因一致**：S02 的值路径、单选/多选语义分别遵守 FormDef 和业务 provider；S03 返回后主表单有正确摘要。
- [ ] **上传真实性**：本地、排队、成功、失败、不可确定、只读状态清楚；不能因为 Mock UI 美观就凭空显示已上传。
- [ ] **完成门禁**：未满足必填/能力时 S05 不可越过限制；保存和完成分离；真实命令维持 fail-closed。
- [ ] **视觉签收单独进行**：和批准的 S01–S05 设计图逐项比对，无工程调试层主导画面；`CODE_PASS` 和 `SCREENSHOT_PASS` 不能代替 `COMMERCIAL_UI_ACCEPTED`。
- [ ] **平台验证**：微信 DevTools/设备、底部安全区、长中文、输入键盘、相机/相册权限须在后续 S3 单独验收。

## 4. 当前决议与不在本轮范围

- **冻结**：S01–S05 的商业化视觉方向与局部交互外观；S02–S05 是辅助交互，不是新的用户完成勘查必经步骤。
- **不冻结**：历史 Survey 61 行字段为生产活动表单、示意工单/照片、当前可用 API、后端权限或真实工作流完成能力。生产活动 FormDef / FormData 证据仍待独立 #124 gate。
- **本轮不改 UI 源码，不合并 #126/#127 的实验性视觉实现**。先把本标准转为设计实现对照，再按照已批准的视觉和现有 Runtime 分层实施。
