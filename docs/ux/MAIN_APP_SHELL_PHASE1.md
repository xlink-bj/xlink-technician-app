# 工匠端四入口骨架 · 第一批

基线：`main` 的 `7afc73f6`。应用一级入口为工作台、工单、通知、我的。底栏和工作台入口统一通过 `redirectTo` 替换根页，避免往返时累积页面栈；工单详情、通知详情和既有作业页位于子页面栈，不渲染底栏。工单筛选和列表保存在原 Pinia store，身份 scope 变化时按原守卫清空。

工作台提供当前用户名/角色、真实工单入口和五类现有工单筛选快捷入口。未在首页计算“今日总数”。我的展示会话已提供的身份、已配置的协议入口、manifest 对应版本和退出确认；没有角色切换、资料修改或忙碌开关。

通知目前没有正式读取/已读 API。隔离 DEV Mock 的三条合成事件仅用于演示列表、阅读、详情和关联工单跳转；阅读状态只在当前内存会话内按身份 scope 保存，并在退出、失效或切账号时立即清理，不触发工单处理。跳转会重新核对当前账号工单列表与现有 `workOrderListActionFor` 详情可达性，目标不可见时拒绝；详情本身继续走原有二次授权。非 Mock 环境明确显示通知尚未接入，不展示伪空列表或伪已读状态。真实通知 API 与服务类型/业务阶段联动留待后续协议确认。

样式分别位于 `src/brands/xlink` 与 `src/brands/yuhong`；雨虹用现有 v2 语义 token，选中态为评审红。`src/pages` 不放品牌色值。开发截图仅在本地忽略目录 `.review/main-shell/{xlink,yuhong}`；430×932 截图来自真实 UniApp H5、隔离 Mock 会话，未使用生产数据。原生设备验证仍待 Mac 串行执行，构建成功不等于实机通过。
