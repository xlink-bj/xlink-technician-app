# B2-X2｜Mock/Real 商业 UI 同构与独立 QA（2026-10-26）

**Owner 决策：同一业务状态与同一权限下，不论数据来自 Mock 还是真实 API，业务 UI 的信息架构、组件、字号、间距、操作和文案应完全相同。** 研发过程中的环境出处、合成 ID、验收说明和调试开关不属于业务 UI。

## 1. 决策边界

1. 商业页面是唯一的产品展示：登录、首页、工单列表、工单详情、表单/勘察/预约、报价/订单、签约状态。Mock 应提供业务可信的客户姓名、地址、编号、状态及内容，不显示 `MOCK-019`、`体验数据`、`未提交后台`、`开发核验` 等标记。
2. 一切 QA 信息集中在独立 `/pages/dev/qa-console`，包括数据源切换、场景入口、草稿诊断、SKU 对照、签约合成核对与进度检查。该页面受 `import.meta.env.DEV && isBusinessMockDeveloperModeAvailable()` 限制；普通导航无入口。旧 `/#/pages/index/index?devReview=1` 只作迁移用重定向，不再把 QA 插入首页。独立 SKU/签约/子流程核验页均只能从 QA 工具链进入。
3. **状态真实、权限真实。** 只读、无权限、失败、未知结果、草稿未提交等业务状态仍应显式且简洁地反馈，但不得用 “Mock 模拟/本机技术校验” 解释实现细节。前端文字不能将仅存于本地的资料伪称已由正式服务端接收；UI 清理不授权新增写入。
4. 合成 fixture 的内部键可以继续使用 `mock-*` 用于测试路由和隔离；**客户看到的字段**必须为正常业务格式。数据源不应成为改变工单详情布局的 CSS 条件，统一使用跨数据源宽度和容器策略。
5. H5/微信小程序/其他平台复用业务布局与语义；H5 Chromium 视觉测试不等于 Mac 微信开发者工具的原生验收。

## 2. 实际实施及验收点

| 范围 | 商业页行为 | 独立 QA 行为 |
| --- | --- | --- |
| 登录与首页 | 正常账号文案、任务入口、清晰业务 CTA；无 Mock 来源/场景面板 | Mock/Real 切换、空/有数据、场景入口、草稿诊断 |
| 工单列表/详情 | 真实业务名称与编号、状态、任务和业务动作；布局不按 Mock ID 分叉 | 通过场景链接进入对应业务流程，核对内部 ID 和状态 |
| 勘察与动态表单 | 填写、保存、完成、异常反馈均采用业务语言 | 合成状态转移/回读由 DEV 工具与日志判定 |
| 报价、订单、SKU | 草稿、报价、金额、材料规格及可执行/不可执行状态 | SKU 唯一性、真实合同不可写边界和 Mock 商业链路检查 |
| 签约只读 | 订单编号、金额核验、合同读取结果、禁用操作 | 合成订单/合同样例、协议与预检证据留在 QA/测试 |

**架构要求：** Mock→adapter→相同 DTO/read model→同一 Vue 组件；DEV QA 不参与组件可见性、字号或布局决策。业务能力不同可因真实权限或读回状态表现不同；不能因 `dataSource === mock` 出现工程标志。`workOrderNumberDisplay` 对业务编号的呈现与 QA 开关无关。

## 3. 自动化门禁

- `node scripts/check-b2x2-commercial-ui-parity.mjs` 扫描 16 个业务模板，禁止技术验收文案/控件穿透，并检查 DEV QA 独立路由、Mock/Real 编号呈现、统一工单布局；纳入 `verify`。
- `tests/g4ux/work-order-number-display.test.ts` 对相同业务编号、不同 Mock/Real/开发标志断言同一 UI 输出。
- `tests/h5-main-mock/b2x-presentation-separation.spec.ts` 在真实 uni-app Main H5 的 375×667 与 390×844 验证默认首页无开发标志、签约 C01 无技术出处、QA 入口独立且返回后首页洁净；禁止外部网络，输出可下载的 PNG/Trace。GitHub Actions 每次在精确 SHA 上运行。
- 全量 TypeScript、单测、H5 和 MP 构建继续保留；旧 DS02A Goldens 因视觉与业务数据变化产生的差异需独立 Owner 判断，严禁未经批准自动更新。

## 4. 不能被本次 Slice 冒充的结论

- `CODE_PASS` 不等于 `H5_BROWSER_PASS`，H5 不等于原生 `MP_DEVICE_PASS`。
- “已完成 Mock 业务流程”不代表已写入 Beta 或 Production；不存在以 QA 参数开启真实写入的权力。
- 视觉一致性需要在同一业务状态和相同可见字段下比对；真实 API 权限只读、数据缺失和错误仍会带来正常的业务状态差异。
- Owner 的商业化视觉验收必须以截图、真实操作手感和整条流程体验为基础，独立于研发 PASS。
